# 外部文件修改检测与自动重载 设计

日期:2026-11-11
状态:已确认

## 目标

1. 打开的文件被其他程序修改后,程序能自动感知,不需要重新打开。
2. 没有未保存改动时,静默重新加载磁盘内容,尽量保持光标/选区/滚动位置。
3. 有未保存改动时,不覆盖用户正在编辑的内容,只给出提示;保存前确认覆盖。
4. 文件被删除或重命名时,保留当前内容并提示。
5. 保持现有不变量:文档文本与 Markdown 源码逐字一致;不改变标题固定为 `Zypora` 的行为。

## 行为规则

### 无未保存改动

- 检测到磁盘内容与程序最后读写的磁盘内容不同,且当前文档无未保存改动:
  - 静默重载:重建文档、更新 `_savedText`、重置撤销栈,不弹窗、不显示提示。
  - 光标与选区按字符偏移恢复(越界则夹到文本长度);滚动位置尽量恢复。
  - 若新旧内容一致(仅时间戳变化),忽略。

### 有未保存改动

- 检测到外部修改时不改动编辑区内容,工具栏显示常驻提示:
  - 「文件已在外部修改,保存将覆盖」
- 该状态下按 `Ctrl+S`:
  - 先用主题化确认窗询问「覆盖 / 取消」;取消则不写入。
  - 覆盖成功后清除提示,并以新内容更新记录的磁盘内容。
- 该状态下用户可主动选择「文件 → 重新加载」放弃本地改动,走现有「保存 / 不保存 / 取消」确认后从磁盘重载。

### 文件被删除 / 重命名

- 工具栏提示「文件已被删除,保存将重新创建」,编辑区内容保留。
- 保存时按新内容重新创建文件,并清除提示。
- 重命名保存(临时文件+替换)按修改处理,不提示删除。

### 自身写入忽略

- 程序保存后会收到文件系统事件;通过与「记录的磁盘内容」比对忽略自身写入,避免误判为外部修改。
- 事件处理时若读到的内容等于程序最后一次写入的内容,直接忽略,不提示、不重载。

### 监听生命周期

- `LoadFile` 成功、另存为到新路径后:启动监听(监听所在目录,按文件名过滤)。
- 清空文档、新建窗口、关闭窗口、未打开文件:停止监听。
- 窗口重新激活时补查一次文件修改时间作为兜底(捕获监听丢失/缓冲溢出);只有时间变化时才读盘。

### 读取失败

- 外部程序写入瞬间可能短暂占用文件:读取失败时最多重试 3 次(每次约 120ms),仍失败则忽略本次事件;窗口激活兜底会再次检查。

## 组件

- `FileChangeMonitor`(新增,可单测)
  - 构造:文件路径、读取文件内容回调、变化回调。
  - 内部:`FileSystemWatcher` 监听目录,`Changed` / `Created` / `Deleted` / `Renamed` 统一 300ms 防抖。
  - 记录程序最后一次读写的磁盘内容 `_diskText`;变化事件读取文件后:
    - 内容等于 `_diskText` → 忽略;
    - 否则更新 `_diskText` 并上报新内容;
    - 文件不存在 → 上报删除。
  - `UpdateDiskText(string)` 供保存后同步;`Refresh()` 供窗口激活兜底(比对修改时间后读盘)。
  - `Dispose()` 释放 watcher。
- `ExternalFileChange`(判定纯逻辑)
  - `Decide(string diskText, string currentText, bool dirty)` → `Ignore` / `Reload` / `Conflict`;
    - `diskText == currentText` → `Ignore`(并清除既有冲突提示);
    - `!dirty` → `Reload`;
    - 否则 → `Conflict`。
- `MainWindow`
  - 新字段:监听器、`_fileConflict`、`_fileDeleted`(磁盘内容由 `FileChangeMonitor` 记录,避免两处状态不一致)。
  - `LoadFile` 后接入监听;`Save` 成功后调用监听器的 `UpdateDiskText`;`ClearDocument`/新建/关闭时释放。
  - 新增 `FileStatusText`(工具栏,与更新状态文字并列),用于常驻文件提示。
  - `ApplyExternalChange(string text)` / `ApplyExternalDeleted()`(internal,便于测试):执行上述判定与 UI 更新。
  - 冲突或删除状态下保存前用 `ConfirmWindow` 确认「覆盖 / 取消」。
  - 文件菜单新增「重新加载」:仅打开文件时可用;有改动时先确认,然后 `LoadFile` 当前路径。
- 不新增设置项;行为固定。

## 测试

- `ExternalFileChange.Decide`:内容相同 → `Ignore`;无改动 → `Reload`;有改动 → `Conflict`。
- `FileChangeMonitor`(临时目录真实文件):
  - 外部写入后在 2 秒内上报新内容;
  - 程序自身写入(先 `UpdateDiskText`)后不触发上报;
  - 临时文件重命名替换能触发;
  - 删除文件上报删除;
  - `Dispose` 后不再上报。
- `MainWindow`(窗口级,反射调用,不注入键鼠):
  - 无改动时外部内容变化 → 文档内容更新、光标尽量保持、`_savedText` 同步;
  - 有改动时外部内容变化 → 文档不变、提示可见、`HasUnsavedChanges()` 仍为真;
  - 删除提示与保存清除提示。
- 既有 378 项测试保持通过;构建 Debug/Release 0 警告 0 错误。

## 不在本次范围

- 多窗口同时打开同一文件时的冲突协调。
- 外部修改时自动把窗口切到前台。
- 文件编码/BOM 策略调整(沿用现有 `File.ReadAllText`)。
