# 清空确认 / 清空可撤销 / 退出保存提示 — 设计

日期:2026-10-21
状态:已确认

## 目标

1. 点击「清空」时先确认,避免误清已保存或已编辑的内容。
2. 新建时生成的默认(欢迎)内容、以及空白内容,清空不需要确认。
3. 所有清空都可通过 `Ctrl+Z` 撤销,`Ctrl+Y` 重做。
4. 编辑后直接关闭窗口时,询问是否保存。
5. 上述提示统一使用应用内主题化弹窗(跟随常规/夜间/护眼主题)。

## 行为规则

### 清空

- 需要确认的内容:非空白,且不等于新建时的欢迎模板。
- 不需要确认的内容:空白(含仅空白字符)或等于欢迎模板。
- 确认弹窗:标题「清空文档」,正文「确定要清空当前文档吗?清空后可以按 Ctrl+Z 撤销。」,按钮「清空」/「取消」。
- 清空前把「原文 + 光标位置」压入撤销栈;清空后不再重置撤销历史。
  - `Ctrl+Z` 恢复原文与光标;`Ctrl+Y` 再次清空。
  - 清空后文档变为「未命名」(`_currentFile = null`),撤销不回原文件路径。
  - 清空后内容与 `_savedText` 一致,不算未保存改动;撤销恢复非空内容后算改动。
- 新建窗口内部复用清空流程时使用 `undoable: false`,不产生多余的撤销步骤。

### 退出

- 关闭窗口(✕ / Alt+F4)时,若有未保存改动:
  - 「保存」→ 保存成功后关闭;另存对话框取消或写入失败则不关闭。
  - 「不保存」→ 直接关闭。
  - 「取消」/`Esc` → 留在窗口。
- 「新建窗口」与「打开文件」前的未保存提示共用同一弹窗与同一套决策。

## 组件

- `ConfirmWindow`(新):主题化模态弹窗,支持 1~3 个按钮;`Primary` 高亮并响应回车,`Cancel` 响应 `Esc`;结果枚举 `ConfirmResult { Primary, Secondary, Cancel }`;提供静态 `Ask(...)`。
- `ClearPolicy`(新):纯逻辑 `NeedsConfirm(text, defaultText)`,便于单测。
- `MainWindow`:
  - 记录 `_welcomeText`(启动时欢迎模板的实际源码文本)。
  - `OnClear` 按 `ClearPolicy` 决定是否弹确认。
  - `ClearDocument(bool undoable = true)` 记录撤销步骤、不重置历史。
  - `ConfirmDiscard` 改用 `ConfirmWindow`(保存/不保存/取消)。
- 现有保存/错误提示仍用系统 MessageBox,不在本次范围内。

## 测试

- `ClearPolicy`:空文本、仅空白、欢迎模板 → 不确认;普通文本 → 确认。
- 清空的撤销/重做:`Reset("old")` → `Command("old")` → 清空为 `""` → `Undo("", 0)` 回到 `old` → `Redo()` 回到 `""`。
- 手动:三套主题下弹窗配色、按钮顺序、`Esc`/回车行为。
